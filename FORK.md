# Форк AmneziaVPN

Это форк [amnezia-client](https://github.com/amnezia-vpn/amnezia-client) для
закрытого VPN-сервиса на AmneziaWG. Лицензия — GPL-3.0, как у оригинала.

## Что изменено

- **Брендинг через CMake.** `brand/brand.cmake` задаёт имя приложения, имя
  службы, организацию и адрес API. Значения можно переопределить через `-D`.
- **Список серверов из своего API.** Новый `ProviderController` при старте
  запрашивает `<API>/v1/servers`, импортирует конфиги как native-подключения и
  обновляет их при повторном запросе.
- **Кнопка обновления** в настройках: *Refresh VPN servers*.
- **Заголовок окна** берётся из имени приложения, а не из жёстко прописанной
  строки.

Больше ничего в поведении клиента не менялось.

## API

### `GET /v1/servers`

Заголовки:

```
X-Device-Id: <uuid>          # генерируется клиентом один раз и хранится локально
Authorization: Bearer <key>  # необязательно, если сервер использует токены
```

Ответ:

```json
{
  "servers": [
    {
      "id": "de-1",
      "name": "Германия",
      "countryCode": "DE",
      "config": "[Interface]\nPrivateKey=...\nAddress=10.66.10.12/32\n...\n[Peer]\nPublicKey=...\nEndpoint=de1.example.com:51820\nAllowedIPs=0.0.0.0/0, ::/0\n"
    }
  ]
}
```

`config` — полный клиентский конфиг AmneziaWG для конкретного устройства.
Сервер должен генерировать отдельную пару ключей на каждую пару
«устройство + узел»: приватный ключ уходит только в конфиге, на сервере
остаётся публичный.

`id` используется для дедупликации: повторный ответ с тем же `id` обновляет
существующее подключение, а не создаёт второе.

Клиент принимает только native-конфиги (WireGuard/AmneziaWG/OpenVPN/Xray в
текстовом виде). Amnezia-конфиги с SSH-доступом и подписки отклоняются.

### Идентификация устройства

Сейчас клиент присылает случайный UUID в `X-Device-Id` и не имеет экрана
ввода приглашения. Для закрытого сервиса добавьте один из вариантов:

- статический токен в `Conf/providerToken` (задаётся через API контроллера);
- экран ввода инвайт-кода, который сохраняет токен;
- привязку к Telegram-аккаунту через отдельный flow.

## Проверка без бэкенда

```powershell
py tools\mock-provider\server.py --port 8080
```

Затем собрать с `-DCLIENT_PROVIDER_API_URL=http://127.0.0.1:8080` или
запустить с переменной окружения `PROVIDER_API_URL`.

Мок отдаёт три сервера с детерминированными фиктивными ключами. Выдача JSON
проверена тестами; импорт и список в приложении ещё не проверены сборкой.
Реальное подключение с этими ключами невозможно.

## Сборка

См. `BUILD_WINDOWS.md`. Кратко:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\build_windows.ps1
```

## Что дальше

1. Заменить иконки и цвета (`brand/assets/README.md`).
2. Поднять реальный API выдачи конфигов и связать его с узлами AWG.
3. Добавить экран ввода инвайт-кода и статус подписки.
4. Подписать exe сертификатом, иначе Windows SmartScreen будет предупреждать.
5. Выложить исходники форка — этого требует GPL-3.0 при раздаче бинарников.

## Ограничения текущего этапа

- Бэкенда нет: есть только контракт API и мок.
- Токен не запрашивается у пользователя, только если задан программно.
- Автообновление списка — раз в запуск и по кнопке, без периодического опроса.
- Удалённые с сервера узлы не удаляются из клиента автоматически.
